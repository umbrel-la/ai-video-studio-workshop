# SaaS Motion Kit: подача проморолика

Если рядом есть `studio-location.json`, прочитай его: `bundle_root` указывает папку полного набора. Все команды ниже запускаются из неё; относительные ссылки разрешай по соответствующему `skills/<имя>/SKILL.md` внутри набора. Если папка перемещена, открой её новый путь и повтори setup в новый каталог скиллов; существующие папки установщик сохраняет.


Сначала прочитай [контракт учебной студии](../../references/motion-v2-contract.md). Этап: Отдельный промоформат: бриф, тема, storyboard.

Включай для product promo, feature reveal или launch, не для обычной правки говорящего рилса. Сначала свяжи одно сообщение, аудиторию, реальные возможности продукта, тон и результат. Исходные creative/tone-matrix, component-forge, transition-atlas и themes дают варианты языка; тема выбирается под материал, а не по эффектности примера.

Storyboard хранит shot ID, takeaway, источник факта, visual event, entrance/transition, camera, sound и reference ID. Повтор допустим как мотив; случайная одинаковость — повод изменить одну из сцен. Для локальной проверки: `node scripts/motion-variety.mjs <plan.json>`. Формат примера — `motion/v2/plan.example.json`. История при необходимости лежит в каталоге ролика, не в домашнем ~/.motion-ledger.json.

Реальные экраны сохраняй подлинными; схематичный imaginary component обозначай иллюстрацией, он не доказывает реальную функцию/клиентов/показатели. Обязательных семи остановок, трёх семейств переходов, новой компоненты на каждый фильм и 4K-рендера здесь нет. Используй уже полученное поручение и настройки текущего проекта. Сценарий владельца и его продукт важнее эстетических запретов автора набора.

Результат: BRIEF/storyboard с фактами, выбранная тема, осмысленная variation review и редактируемый HyperFrames-проект, переданный существующему монтажному процессу.
